# 认证连接诊断与修复

## 已确认的故障边界

2026-10-27 06:38 UTC，使用与 App 相同的 `com.continuousauth.proto.SensorDataService/SendHeartbeat` RPC 进行只读检查：

| 入口 | 结果 |
| --- | --- |
| 本机 `127.0.0.1:10500`，h2c | 心跳成功，返回服务端时间及客户端时间戳回显 |
| 公网 `ca.macrz.com:443`，系统可信 TLS | `UNAVAILABLE: Received http2 header with status: 504` |

公网检查显式禁用了 Python gRPC 的 HTTP 代理；没有发起认证会话、采集传感器数据或上传测试数据。原始结果在构建产物 `app/build/reports/network-audit-2026-10-27/readonly-heartbeat.json`。

这表明后端 RPC 在本机可用，公网入口能完成 TLS/HTTP2 连接，但公网代理链路没有成功返回实际认证 RPC。浏览器能访问服务器、TCP 能连通或 HTTP/2 通道进入 `READY`，都不能证明认证服务可用。此次没有修改或重启生产服务器。

## 客户端修复

- 连接成功必须收到合法心跳响应，不再只凭通道 `READY` 或创建了流对象报告成功。探测不包含设备标识或传感器数据。
- 设置页连接测试使用独立通道，总是测试所填地址；成功、失败和取消均关闭探针，不会借用或断开后台上传通道。
- 认证请求和心跳改为可取消的异步 RPC；停止操作会取消尚未完成的调用。连接失败保留可读原因，明确区分服务器 504、DNS、证书、超时和服务不支持。
- 保存新地址后，运行中的上传管理器会应用新端点并重连，保留待传数据；旧认证需要在新服务器重新开始。
- 所有显式 HTTPS 端点都保持 TLS，失败不静默降级成明文。自建 h2c 服务器需要明确填写 `http://` 与实际端口。
- 修复证书固定管理器被创建却未加入 SSLContext 的问题；固定证书仍必须通过系统证书链及主机名校验。
- IPv6 地址保存与重新解析保留方括号；拒绝超出有效范围的端口。
- Android 互联网验证探针失败不再被当作上传能力的绝对判断；最终可用性由实际 RPC 决定。当前上传主循环原本没有使用该验证门，因此此项不是本次公网 504 的根因。
- 移除诊断信息和上传缓冲统计的主线程阻塞，TLS 能力信息在 IO 线程读取。

## 服务端仍需确认的事项

本次域名解析将 `ca.macrz.com` 指向 `tx.macrz.com` / `192.144.225.178`。公网代理不在本机；本机 Nginx 配置中没有该域名的站点。

相邻服务端仓库的部署模板使用：

```nginx
grpc_pass grpc://127.0.0.1:10500;
```

这是**仓库模板**，无法据此确定公网当前实际配置。`127.0.0.1` 只适用于代理与后端处于同一主机、同一网络命名空间的部署；远程代理或独立容器需要后端实际可达的内部地址。未经现场配置和日志验证，不能把 504 进一步断言成某一个具体上游地址错误。

服务管理员应在公网 OpenResty 的网络命名空间内：

1. 查看 `nginx -T` / `openresty -T` 中该域名实际使用的 `location` 和 `grpc_pass`，以及相应错误日志中的 upstream 地址与失败原因。
2. 使用同一命名空间访问实际 upstream 的只读心跳或 gRPC Health/Check，验证路由、端口和防火墙。
3. 保持公网 `443/TLS+h2`；后端目前本机 `10500` 是 h2c，上游应使用 `grpc://`。如实际后端启用 TLS，应匹配 `grpcs://` 及证书校验设置。
4. 如果代理与后端分离，将上游配置为经过验证的内部地址，并完成语法检查、受控 reload 和公网心跳复验。

## 回归方式

JVM 测试通过本地受控的真实 gRPC 服务验证心跳、错误服务、504、HTTPS 不降级、连接切换、探针隔离、请求取消及离线队列保留；TLS 测试验证证书链和 SPKI 双重约束。

Android 设备的只读检查类为 `com.continuousauth.network.ServerHeartbeatInstrumentedTest`。默认不访问外网；显式传入 `serverHeartbeatEndpoint` 后只调用心跳。可使用临时 `adb reverse` 映射到本机后端验证 Android 实际网络栈，结束后删除映射。

当前加密协议仍与服务端一致：静态共享 AES-256-GCM、`IV | tag | ciphertext`、不使用 AAD。不能只在 App 单端改变密钥交换或开启 AAD，否则会破坏服务端解密。此次仅修复合法空明文密文的解密长度边界；完整密钥管理升级需要客户端与服务端共同设计和迁移。
