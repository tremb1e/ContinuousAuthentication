# 业务流程说明

更新日期：2026-06-03

## 1. 启动与授权

1. App 启动后初始化 Hilt、时间同步、监控组件和隐私状态。
2. 用户必须完成隐私同意、Usage Stats、通知/前台服务等必要权限。
3. 未授权时，`MainViewModel.startEncryptedUpload()` 会阻止采集和上传。

## 2. 服务器配置

1. “服务器配置”页面读取保存的 host、port、scheme；默认公网入口为 `https://ca.macrz.com:443`。
2. 用户输入 `ca.macrz.com:80`、`http://ca.macrz.com:80` 或旧的 `ty.macrz.com:10500` 时，App 会保存为 `https://ca.macrz.com:443`。
3. “检测服务器”调用 `MainViewModel.testServerConnection()`，只做一次性 TLS/HTTP2 gRPC 探测，不启动采集，也不直接访问后端 `ty.macrz.com:10500`。
4. “加密数据上传”调用 `MainViewModel.startEncryptedUpload()` / `stopEncryptedUpload()`。
5. 页面展示“上传标识 (HMAC)”，该值与 `DataPacket.device_id_hash` 一致。

## 3. 采集与上传

```
SensorManager
  -> SensorCollectorImpl
  -> SensorDataProcessor.chunked(1s)
  -> DataPacketBuilder.buildSensorBatch()
  -> CompressionManager(LZ4)
  -> EnvelopeCryptoBox.encrypt()
  -> DataPacketBuilder.buildDataPacket()
  -> FileQueueManager / InMemoryBuffer
  -> UploadManager
  -> UploaderImpl gRPC StreamSensorData
  -> ca-server
```

关键点：

- `SessionManager.startNewSession()` 每次启动上传生成新的 session。
- `SerializedSensorBatch` 只包含 `samples` 与 `session_id`。
- `foregroundApp` 作为 `foreground_app_name` 写入样本，内容为当前前台应用明文包名。
- `EnvelopeCryptoBox` 使用稳定设备材料生成 `device_id_hash`，不依赖用户 ID。
- 数据包加密格式为 `IV(12)|TAG(16)|ciphertext`。

## 4. Server 处理

1. gRPC server 接收 `DataPacket`。
2. 校验 `device_id_hash` 是否适合作为存储路径片段。
3. 对 `encrypted_sensor_payload` 执行 AES-GCM 解密。
4. 按 `metadata.compression` 或魔数执行 LZ4/GZIP 解压。
5. 将明文解析为 `SerializedSensorBatch`。
6. 写入 raw storage，并返回 `Ack`。
7. 若该 session 已启动认证，server 将批次交给认证模块并下发 `AuthResult`。

## 5. 认证流程

1. 用户在持续认证页发起认证。
2. App 校验当前必须已连接并处于加密上传中。
3. App 调用 `StartAuthentication`：
   - `device_id_hash = EnvelopeCryptoBox.getDeviceIdHash()`
   - `session_id = SessionManager` 当前 session
   - `app_version`
   - `android_api_level`
4. server 返回是否接受认证、模型版本、窗口大小和最长决策时间。
5. 后续每个可判定窗口由 server 在 gRPC 流中下发 `AuthResult`。
6. App 校验 `session_id` 和 `device_id_hash` 后更新 UI。

## 6. UI 展示

持续认证页的实时判定数据全部来自 server：

- 模型名称：`StartAuthentication.model_version` 或 `AuthResult.model_version`。
- 判定结果：`AuthResult.accept` / `AuthResult.interrupt`。
- 分数：`AuthResult.normalized_score`。
- 阈值：`AuthResult.threshold`。
- 窗口编号：`AuthResult.window_id`。
- 窗口大小：`AuthResult.window_size_sec`。
- EMA / y-of-x：`AuthResult.message`。

“恶意用户检测日志”在每次成功启动认证会话后清空，只追加当前会话前 10 条 `accept=false` 的认证结果。相对时间由 App 根据 `server_timestamp_ms` 动态格式化。

## 7. 停止与清理

1. 停止上传会停止采集、上传循环、监控刷新和当前 session。
2. 撤回隐私同意会调用本地清理流程，清除缓存、Room/文件队列和 session 数据。
3. 清理后上传标识仍由硬件材料重新计算；普通卸载重装不会因为本地私有存储删除而改变上传标识。
