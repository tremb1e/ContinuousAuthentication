# 业务流程说明

## 1. 端到端主流程

1. **应用初始化**
   - `ContinuousAuthApplication` -> `EnhancedTimeSync.syncTime()`（启动 + 每小时）。
   - Hilt 注入核心组件（`SensorCollectorImpl`、`PrivacyManager`、`SmartTransmissionManager` 等）。
2. **用户授权**
   - 首次进入 `MainActivity` 弹出隐私协议、Usage Stats、忽略电池优化等对话框。`PrivacyManager` 记录同意状态。
   - 未同意时 `startCollection()` 会被拦截。
3. **启动采集服务**
   - 用户点击 “开始采集” -> `DataCollectionService` 前台服务启动，获取 `WakeLock`，注册系统广播。
   - `SmartTransmissionManager.start()` 初始化 Sensor、Buffer、Upload、监控协程。
4. **数据采集 & 打包**
   - `SensorCollectorImpl` 每个传感器按目标采样率注册监听，1 秒窗口批量写入 `RingBuffer` / `sensorDataChannel`。
   - `SensorDataProcessor` -> `CompressionManager` -> `EnvelopeCryptoBox` -> 生成 `DataPacket`。
5. **缓存 & 上传**
   - `InMemoryBuffer` 先行入队；超过上限或持久化策略触发写入 `FileQueueManager` (Room+磁盘)。
   - `UploadManager` 依据 `NetworkEnvironmentDetector` 状态决定是否出队上传。
   - `UploaderImpl` 建立 gRPC Stream，或由 HTTP Lite 客户端 POST `/api/v1/sensor-data`（用于当前 server-lite）。
6. **Server 处理**
   - FastAPI 接收请求 -> `AESDecryptor` -> `DataDecompressor` -> `PacketValidator` -> `FileStorage` (JSONL)。
   - 产生 `{"status":"ok"}` 响应，或在 gRPC 流中下发 `Ack/PolicyUpdate`。
7. **回执 & 调整**
   - `UploaderImpl` 根据 `Ack` 更新 `pendingAcks`，计算往返延迟；`PolicyUpdate` 触发 `PolicyManager.updatePolicy()` 并动态调节 `SmartTransmissionManager`。
8. **监控与终止**
   - `SystemMonitor/MetricsUploader` 周期上报系统资源；`DataCollectionService` 监听电池/充电广播自动 `pause/resume`。
   - 用户点击 “停止采集” 或撤回隐私同意，关闭服务并清理缓存。

## 2. Android 端子流程

### 2.1 初次启动 & 权限

1. `MainActivity` -> `checkFirstLaunchFlow()`：
   - 展示 `PrivacyAgreementDialog`，同意后 `PrivacyManager.grantConsent()`。
   - 引导打开 Usage Access (`UsageStatsPermissionDialog`)。
   - 提示忽略电池优化 (`BatteryOptimizationDialog`)。
2. 状态写入 SharedPreferences/EncryptedSharedPreferences，`MainViewModel` 在 `onResume` 再次校验。

### 2.2 数据采集链

```
SensorManager → SensorCollectorImpl → currentWindowSamples (1s) 
 → SensorDataProcessor.chunked() → SerializedSensorBatch 
 → CompressionManager(GZIP/LZ4) → EnvelopeCryptoBox(AES-256-GCM) 
 → DataPacketBuilder(DataPacket) → InMemoryBuffer/FileQueueManager 
 → UploadManager → UploaderImpl/gRPC
```

关键控制点：

- `EnhancedTimeSync.convertToAbsoluteTime()` 提供窗口基准，Server 以 `timestamp_ms/window_*` 对齐。
- `UserIdManager.startNewSession()` 每次启动采集生成 `session_xxx`，写入 `DataPacket.session_id`。
- `SmartTransmissionManager.updatePolicy()` 可动态调整 `batchInterval`、`maxPayloadSize`、`compressionEnabled` 与 `encryptionEnabled`。

### 2.3 连接状态机

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| `DISCONNECTED` | 初始 / `UploaderImpl.disconnect()` | 停止上传，等待 `start()` |
| `CONNECTING` | `UploaderImpl.connect()` | 构建 TLS1.3 gRPC channel（OkHttp/KeepAlive 30s） |
| `CONNECTED` | 双向流建立成功 | `serverDirectiveChannel` 接收 Ack/Policy，`pendingAcks` 跟踪 |
| `RECONNECTING` | 网络抖动、`onError()` | 指数退避 (1s→30s)、最多 3 次重试 |
| `ERROR` | 重试失败 / ACK 超时 | `UploadManager` 记录 `connectionErrors`，等待人工或下一次 start |

`UploadManager` 根据状态更新 `MainViewModel.connectionStatus`，UI 上显示连接图标/颜色。

### 2.4 暂停 / 恢复策略

- 系统事件：`ACTION_BATTERY_LOW` -> `pauseCollection()`；`ACTION_POWER_CONNECTED` -> `updateCollectionStrategy(isCharging=true)`（批次 500ms、关闭压缩）。
- 用户手动：通知栏 Action / 主页面按钮。
- 暂停后仍保持服务存活，但 `SensorCollectorImpl` 停止注册监听，网络上传暂停。

## 3. Server 侧流程

1. **接收阶段**：  
   `receive_sensor_data()` 读取 Header 与 `request.body()`，校验 `Content-Length`。
2. **安全阶段**：  
   - `AESDecryptor.decrypt()` -> 需要 12B IV + 16B tag + ciphertext。
   - `DataDecompressor.decompress()` 自动识别 LZ4/GZIP（魔数）或使用 hint。
3. **验证阶段**：  
   `PacketValidator`（Pydantic）核对：device/session/seq 与 Header 一致、时间戳范围 2020~2030、`window_end >= window_start`、`sensor_data` 列表非空。
4. **持久化阶段**：  
   `FileStorage.append_packet()` -> `data_storage/<device_hash>/session_<session>.jsonl`，追加 `server_received_timestamp`。
5. **响应阶段**：  
   成功 `{"status":"ok"}`；失败 `{"status":"error","reason":...}`（如 `decryption_failed`/`validation_failed`/`storage_failed` 等）。所有异常写 JSON 日志。
6. **健康检查**：  
   `GET /health` 返回 `storage_stats`（设备数、session 数、总 MB），供测试验证写入量。

## 4. UI / 页面交互流程

| 页面/模块 | 交互步骤 | 数据来源 |
| --- | --- | --- |
| 主 Dashboard (`ActivityMainBinding`) | ①点击“开始/停止”-> 调用 `MainViewModel.startCollection()` / `stopCollection()`；②`tvCollectionStatus` 根据 `collectionStatus` LiveData 切换颜色；③`tvAccelerometerStatus` 等显示每个传感器是否已注册监听；④`tvConnectionStatus` 显示 `ConnectionStatus`；⑤“显示图表”按钮触发 `SensorChartView`。 | `MainViewModel` 汇总 `UploadManager`、`NetworkEnvironmentDetector`、`SystemMonitor`、`FileQueueManager` 状态 |
| `SensorDataFragment` | 订阅 `SensorDataViewModel.sensorStreams`，Canvas 绘制加速度/陀螺/磁力波形；支持缩放/暂停显示；帧率控制≤30fps。 | `SensorCollectorImpl` -> Flow |
| `ServerConfigFragment` | 可编辑 server endpoint、TLS Pin 文本框，点击“测试连接”调用 `ServerConnectionTester` 进行 HTTP/gRPC 探测。显示当前策略（`PolicyManager` DataStore）和证书校验结果。 | `ServerConfigViewModel` |
| 弹窗 | `PrivacyAgreementDialog`（必须“同意”才启用按钮）、`UsageStatsPermissionDialog`（跳转设置）、`BatteryOptimizationDialog`（引导忽略）。 | `MainActivity` |
| 通知栏 | 前台通知显示 “数据采集运行中/暂停/就绪”，并提供“暂停/恢复”、“停止” Action -> 通过 `PendingIntent` 调用 `DataCollectionService`。 | `DataCollectionService` |

UI 测试需覆盖：状态切换、权限弹窗阻断、数据统计正确刷新、图表显示/隐藏、配置页面读写。

## 5. 异常与恢复流程

| 场景 | 客户端行为 | Server 行为 | 预期 |
| --- | --- | --- | --- |
| 网络断开 | `NetworkEnvironmentDetector` 发布 `DISCONNECTED` -> `UploadManager` 停止 deque，`UploaderImpl` 进入 `RECONNECTING`。 | 无请求 | 无数据丢失，网络恢复后自动续传 |
| ACK 超时 | `UploaderImpl.checkAckTimeout()` 将包保留在 `pendingAcks` 并记录 `connectionErrors`，后续可人工重发（TODO）。 | - | UI 显示“上传重试”，日志包含 `dataPacketId` |
| 解密失败（Server） | 返回 `400 {"reason":"decryption_failed"}`；客户端 `UploadManager` 根据 ACK/HTTP 响应标记失败、写入 `BatchMetadata`。 | `AESDecryptor` 记录错误 | QA 应确认密钥一致与 Header 正确 |
| 权限被撤销 | `MainViewModel.checkUsageStatsPermission()` 发现缺失 -> `_errorMessage` -> UI 弹窗提醒。 | - | 测试需验证 `startCollection()` 被挡 |
| 隐私撤回 | `PrivacyManager.withdrawConsentAndDeleteData()` 清空 Room/文件/缓存、调用 (TODO) server 删除接口；`DataCollectionService` 停止。 | - | QA 验证无遗留文件、`consentState=WITHDRAWN` |
| Server 写入失败 | 返回 500，`UploadManager` 将包标记 `FAILED` 并保留文件，等待下一次 `uploadBatchFromBuffer()`。 | `FileStorage` 记录原因 | 日志/health 应显示错误 |
