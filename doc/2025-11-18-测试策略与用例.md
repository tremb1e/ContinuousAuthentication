# 测试策略与用例

## 1. 测试目标

1. 验证 Android 端能在取得授权后，按 1 秒窗口采集加速度计/陀螺仪/磁力计数据，并生成符合 `DataPacket` 协议的加密包。
2. 验证网络连接（gRPC + HTTP Lite）能维持 TLS1.3 加密通道、处理 ACK/策略更新、网络切换、离线缓存。
3. 验证 Server `/api/v1/sensor-data` 能解密/解压/校验并落盘 JSONL，`/health` 反映真实状态。
4. 验证 UI（主界面、图表、配置页、权限弹窗）在不同状态下的交互是否正确。
5. 验证隐私合规（同意/撤回、数据删除）与日志/监控可观测性。

## 2. 测试类型

| 类型 | 内容 |
| --- | --- |
| 功能测试 | 采集、打包、上传、服务端处理、策略同步、UI 按钮/状态 |
| 接口互通 | gRPC Stream、HTTP POST（Lite server）、`/health`、ACK |
| 安全与合规 | AES-GCM 密钥一致性、TLS1.3 Pin、隐私撤回清理、权限控制 |
| 性能 & 容量 | 高频采集（200Hz）、长时间运行、缓存上限、Server 大包（10MB）处理 |
| 恢复能力 | 网络切换、Server 故障、ACK 超时、电池低电量暂停/恢复 |
| 观测性 | 日志字段、`MainViewModel.debugInfo`、Server JSON 日志、`/health` 指标 |

## 3. 测试环境与准备

1. **Android 设备**：Android 10+，需具备三轴传感器。安装 Debug 版 APK，打开开发者选项便于抓日志。
2. **权限**：手动确认授予 `Usage Access`、`Ignore Battery Optimization`、`Foreground Service`、`INTERNET`、`PACKAGE_USAGE_STATS`。
3. **Server**：`cd server && pip install -r requirements.txt && python -m src.main`，或 `docker-compose up --build`。确认 `logs/` 与 `data_storage/` 可写。
4. **网络**：建议同一 Wi-Fi，必要时使用热点模拟切换；确保防火墙允许 8000 端口。
5. **工具**：Logcat、Protobuf/gRPC 调试器、`curl`/`httpie`、`jq`，以及数据解析脚本（可读取 JSONL）。
6. **密钥对齐**：确保 `.env` 中 `ENCRYPTION_KEY=Continuous_Authentication`，与 Android 一致；若使用 TLS Pin，填入 `PolicyManager` pinnedCertificates。

## 4. 核心测试用例

| ID | 场景 | 前置 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| F-01 | 首次启动授权流程 | 新安装 | 打开 App，依次处理隐私、Usage、Battery 对话框 | 所有对话框关闭后，“开始采集”按钮可用；`PrivacyManager.consentState=GRANTED`，日志无错误 |
| F-02 | 启动/停止采集 | F-01 完成 | 点击“开始采集”，观察通知栏 & UI；再点击“停止” | 前台服务运行、状态切换 RUNNING→STOPPED、通知文案更新、`DataCollectionService` 收到命令 |
| F-03 | 传感器数据正确打包 | 采集运行 | 运行 5s，抓取 `InMemoryBuffer`/文件队列样本或本地日志 | `DataPacket.metadata` 包含正确 appVersion/schema/compression；`packet_seq_no` 自增；`encrypted_payload` 非空 |
| F-04 | gRPC 连接维持 | Server 支持 gRPC/mock | 启动上传，断网 10s 再恢复 | `UploaderImpl` 进入 RECONNECTING 并自动恢复，`pendingAcks` 无遗留，UI 显示重连提示 |
| F-05 | HTTP Lite 上传 | 通过脚本/工具 | 将 DataPacket 解密/序列化后 POST `/api/v1/sensor-data` | Server 返回 200，`data_storage/<device>/session_xxx.jsonl` 新增记录，字段与规范匹配 |
| F-06 | Server 解密失败 | 修改密钥 | Android 保持默认，Server `.env` 改为其他值 | 接口返回 400 reason=decryption_failed；Server log 记录 request_id；Android `UploadManager` 标记失败并保留文件 |
| F-07 | ACK 流程 | gRPC mock（或模拟 ServerDirective） | 发送 DataPacket，并在流上返回 Ack | `UploaderImpl` 从 `pendingAcks` 删除 packetId，`lastAckLatency` 记录正确 |
| F-08 | 策略更新应用 | 构造 `PolicyUpdate` | ServerDirective 推送 batch_interval=500/compression=lz4 | `PolicyManager` DataStore 更新，对应日志打印；`SmartTransmissionManager.updatePolicy()` 生效（日志/统计变化） |
| F-09 | 离线缓存 & 恢复 | 断网 | 运行 2 分钟后断网 1 分钟再恢复 | 断网期间数据保留在 `FileQueueManager`；网络恢复后自动上传并删除 ACK 包 |
| UI-01 | 传感器状态显示 | 任意 | 关闭某个传感器（开发者工具）或模拟异常 | UI 对应传感器标红 “未启用”；日志出现警告 |
| UI-02 | 图表显示 | 运行中 | 点击“显示图表”，观察波形 | 波形刷新、帧率稳定；隐藏后释放资源 |
| UI-03 | Server 配置 & 探测 | - | 在 ServerConfigFragment 输入错误地址，点击“测试” | 提示连接失败，日志打印原因；输入正确地址时状态为成功 |
| SEC-01 | 撤回隐私同意 | 正在运行 | 点击“停止”，在设置入口触发撤回 | 本地 `data_queue/`、Room、SharedPreferences 清空；UI 状态 `WITHDRAWN`；`PrivacyManager` 日志 |
| PERF-01 | 高频+长时运行 | 夜间运行 | 保持 Wi-Fi & 充电，运行 ≥8h | 无崩溃；`SystemMonitor` 记录 CPU/内存稳定；`data_storage` & 日志增长可统计 |
| OBS-01 | 日志 & health | - | 上传成功/失败各一次，并访问 `/health` | Log 中包含`request_id`、`reason`；`/health` total_sessions/devices 数值正确 |

> 注：若暂未提供 gRPC Server，可通过 `UploaderImpl` 注入 mock stub 或使用脚本模拟 ServerDirective 事件；HTTP Lite 测试可直接对 FastAPI 服务发送密文。

## 5. 缺陷记录与度量

- 使用统一缺陷模板：`模块`、`环境`、`请求ID/packetId`、`日志片段`、`重现步骤`。
- 重点关注：  
  - 数据不一致（Header vs Body）  
  - 时间戳异常（NTP 未同步）  
  - 缓存泄漏（文件未删除、状态未更新）  
  - UI 状态与实际服务不同步
- 度量指标：通过用例比例、残留 Bug 数、平均重连时长、Server 处理失败率。

## 6. 退出准则

1. 所有 **P0/P1** 缺陷关闭或已有明确 workaround，P2 以下评估可延后。
2. 功能用例通过率 ≥ 95%，关键路径（F-01~F-09、UI-01~UI-03、SEC-01）全部通过。
3. 长时间运行（PERF-01）无崩溃、无内存泄露，Server `/health` 无 error。
4. 日志覆盖完整，能够定位常见问题；测试报告中包含流量样本与抓包记录。
