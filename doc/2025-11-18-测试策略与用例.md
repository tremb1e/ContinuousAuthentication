# 测试策略与用例

更新日期：2026-06-03

## 1. 测试目标

1. 验证 App 生成的 `DataPacket` 与 server proto 字段号一致。
2. 验证 `encrypted_sensor_payload` 可被 server 按 `IV(12)|TAG(16)|ciphertext` 解密，并按 LZ4/GZIP 解压。
3. 验证普通卸载重装不会因为本地随机值变化而改变“上传标识 (HMAC)”。
4. 验证认证 UI 只展示 server `StartAuthentication` / `AuthResult` 返回的数据。
5. 验证“认证结果分析”在开始/停止之间累计运行时间、通过次数、不通过次数和通过率。
6. 验证“认证结果分析日志”只保留最近 10 段开始到停止的分析记录。
7. 验证锁屏暂停采集和上传，解锁后在用户此前已启动采集时自动恢复。
8. 验证 APK 可编译生成。

## 2. 环境

| 项目 | 要求 |
| --- | --- |
| Android | Android 10+，具备加速度计、陀螺仪、磁力计。 |
| Server | `/data/code/backup/ca-server`，内部 gRPC 端口 `10500`；App 只通过公网入口 `https://ca.macrz.com:443` 验收。 |
| 权限 | Usage Stats、前台服务、通知、网络、电池优化相关权限。 |
| 密钥 | server `encryption_key` 与 App 均使用 `Continuous_Authentication`。 |

## 3. 核心用例

| ID | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- |
| P-01 | proto 对齐 | 对比 app `app/src/main/proto/sensor_data.proto` 与 server `protos/sensor_data.proto`。 | `SerializedSensorBatch` 无用户标识字段；`foreground_app_name` 为字段 8。 |
| P-02 | 加密包格式 | 启动加密上传，观察 server 日志。 | server 日志显示 decrypt、decompress、parse batch 成功。 |
| P-03 | 上传标识稳定 | 同一设备记录“上传标识 (HMAC)”，卸载重装后再次查看。 | 无硬件/系统标识变化时，两次值一致。 |
| P-04 | 前台应用上下文 | 上传含前台应用的样本。 | server 存储中的 `sensor_batch.samples[]` 包含 `foreground_app_name` 明文包名，不再出现旧的前台应用 hash 字段。 |
| A-01 | 认证启动 | 加密上传中点击开始认证。 | UI 显示 server 返回的 `model_version`、`window_size_sec`、`decision_time_sec` 和 `message`。 |
| A-02 | 认证结果 | server 下发 `AuthResult`。 | UI 显示 `normalized_score`、`threshold`、`window_id`、判定结果和 `message`。 |
| A-03 | 认证结果分析开始 | 点击“开始”，等待 3 秒。 | 运行时间从 0 开始累计；通过/不通过次数为 0；“开始”禁用，“停止”可用。 |
| A-04 | 认证结果分析计数 | 开始分析后依次下发 `accept=true, interrupt=false`、`accept=false`、`interrupt=true`。 | 通过次数为 1，不通过次数为 2，通过率为 33.3%。 |
| A-05 | 认证结果分析停止 | 点击“停止”后继续下发 `AuthResult`。 | 运行时间和计数停止变化，当前统计结果保留。 |
| A-06 | 认证结果分析日志 | 连续完成 12 次开始/停止分析。 | “认证结果分析日志”只保留最近 10 段，每条包含开始时间、运行时间、通过次数、不通过次数、通过率。 |
| A-07 | 重新开始分析 | 停止后再次点击“开始”。 | 当前统计清零并重新计时，历史分析日志保留。 |
| L-01 | 锁屏暂停 | 加密上传运行中锁屏。 | 前台服务暂停传感器采集，并暂停上传循环。 |
| L-02 | 解锁恢复 | L-01 后解锁手机。 | 前台服务自动恢复传感器采集和上传；未启动采集时解锁不会自动启动服务。 |
| UI-01 | 服务器配置页面 | 点击检测服务器、启动/停止加密上传。 | 原有网络传输流程可用，页面显示上传标识，不显示用户 ID。 |
| N-01 | 公网入口归一化 | 在服务器配置输入 `https://ca.macrz.com`，端口输入 `80`，点击检测服务器。 | App 保存并连接 `https://ca.macrz.com:443`。 |
| N-02 | 旧后端地址迁移 | 输入旧地址 `https://ty.macrz.com:10500`，点击检测服务器。 | App 不直连该后端地址，保存并连接 `https://ca.macrz.com:443`。 |
| N-03 | 公网入口失败策略 | 断开或错误配置 `ca.macrz.com:443` 的 TLS/gRPC 入口。 | App 报告连接失败，不回退明文 h2c，不切换到其它端口。 |
| B-01 | 编译 | 执行 `./gradlew :app:assembleDebug`。 | 构建成功并输出 debug APK。 |

## 4. 命令

App 构建：

```
./gradlew :app:assembleDebug
```

单元测试：

```
./gradlew :app:testDebugUnitTest
```

本次新增认证分析逻辑可单独执行：

```
./gradlew testDebugUnitTest --tests com.continuousauth.ui.AuthAnalysisStateTest
```

APK 检查：

```
ls -lh app/build/outputs/apk/debug/app-debug.apk
```

公网 gRPC 健康检查：

```
grpcurl ca.macrz.com:443 grpc.health.v1.Health/Check
```

验收测试只针对 `ca.macrz.com:443`。`ty.macrz.com:10500` 是 OpenResty 后端目标，不作为 App 侧测试入口。

## 5. 验收准则

- 构建通过并生成 APK。
- 公网入口 `ca.macrz.com:443` 的 TLS/HTTP2 gRPC 健康检查通过。
- 运行时代码无旧用户标识管理器、旧用户标识 HMAC 方法或用户标识协议字段。
- App 发送数据可被 server 当前 gRPC 接收链路解析。
- 持续认证页显示的认证数据与 server 返回字段一致。
- 文档描述与当前代码一致。
