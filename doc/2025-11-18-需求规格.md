# 需求规格说明

更新日期：2026-06-03

本文以当前 Android App 和 `/data/code/backup/ca-server` 的代码为准。

## 1. 目标

1. Android App 采集设备传感器数据，按服务端 proto 打包、压缩、加密并通过 gRPC 上传。
2. 服务端接收 `DataPacket`，完成 AES-GCM 解密、LZ4/GZIP 解压、`SerializedSensorBatch` 解析和落盘。
3. 服务端执行持续认证后，通过 gRPC `AuthResult` 下发模型和判定结果，App 负责展示。
4. App 不生成、不保存、不上传用户 ID；上传标识为设备级稳定 HMAC。

## 2. 范围

| 范围 | 当前实现 |
| --- | --- |
| Android App | `/data/code/backup/github/ContinuousAuthentication/app` |
| Server | `/data/code/backup/ca-server` |
| 主协议 | gRPC `SensorDataService` |
| 默认 App 公网入口 | `https://ca.macrz.com:443` |
| Server 内部 gRPC 端口 | `10500` |
| 数据格式 | Protobuf `DataPacket` / `SerializedSensorBatch` |
| 加密格式 | AES-GCM `IV(12)|TAG(16)|ciphertext` |
| 压缩格式 | App 默认 LZ4，server 支持 LZ4/GZIP 自动识别 |

## 3. 功能需求

### 3.1 采集与打包

- App 采集加速度计、陀螺仪、磁力计。
- 样本保留 `event_timestamp_ns`、三轴值、精度、递增 `seq_no`。
- 前台应用写入 `foreground_app_name`，内容为当前前台应用明文包名。
- 每个上传窗口构造一个 `SerializedSensorBatch`：
  - `samples = repeated SensorSample`
  - `session_id = 当前采集/认证会话`
- `SerializedSensorBatch` 不包含用户标识字段。

### 3.2 上传标识

- 服务器路径和认证入口使用 `device_id_hash`。
- `device_id_hash` 由 `EnvelopeCryptoBox.getDeviceIdHash()` 生成。
- 生成算法必须不依赖 App 私有存储中的随机值，保证普通卸载重装后同一硬件输出不变。
- 当前材料按优先级选择：Widevine 设备唯一材料摘要优先，`ANDROID_ID` 次之，多项 `Build.*` 硬件字段兜底；HMAC key 由固定共享 secret 派生。
- HMAC 输出必须使用 URL-safe Base64，满足 server `validate_storage_id()` 对路径字符的限制。

### 3.3 加密上传

- App 先执行 Protobuf 序列化，再 LZ4 压缩，最后 AES-256-GCM 加密。
- `encrypted_sensor_payload` 必须是 `IV(12)|TAG(16)|ciphertext`。
- `metadata.compression` 当前写入 `LZ4`。
- `metadata.encryption_scheme` 当前写入 `AES-256-GCM`。
- `dek_key_id` 当前为静态标识 `STATIC_KEY_V1`；`encrypted_dek` 不再发送有效 DEK。

### 3.4 gRPC 与策略

- App 使用 `UploaderImpl` 建立 gRPC 双向流。
- App 默认连接 `https://ca.macrz.com:443`，通过 OpenResty 反代访问后端 gRPC 服务。
- 用户输入 `ca.macrz.com:80`、`http://ca.macrz.com:80` 或旧后端地址 `ty.macrz.com:10500` 时，App 必须归一化为 `https://ca.macrz.com:443`。
- 公网 `ca.macrz.com:443` 必须使用 TLS/HTTP2 gRPC，连接失败时不得回退明文 h2c 或其它端口。
- `StreamSensorData` 发送 `DataPacket`，接收 `ServerDirective`。
- `Ack` 用于确认上传结果。
- `PolicyUpdate` 可更新传输和采集策略。
- `AuthResult` 必须进入 `UploadManager.authResultFlow`，由 `MainViewModel` 展示。

### 3.5 认证 UI

- 发起认证前必须已经连接服务端并启动加密上传。
- App 调用 `StartAuthentication`，请求字段为 `device_id_hash`、`session_id`、`app_version`、`android_api_level`。
- 页面展示的模型名称、认证结果、窗口大小、决策时间、分数、阈值、窗口编号、EMA 或 y-of-x 文本必须来自 server 响应。
- App 不在端侧自行计算最终认证结论。

### 3.6 恶意用户检测日志

- 持续认证页“近期判定”下方必须有“恶意用户检测日志”。
- 每次成功启动认证会话后重新计数，只记录当前认证会话前 10 次认证不通过结果，即 server `AuthResult.accept == false`。
- 每条日志包含：
  - 具体时间，当前格式为 `HH:mm:ss`；
  - 距离当前的相对时间；
  - 窗口编号、分数、阈值；
  - server 返回的 `message`。
- 相对时间精度：
  - 小于 10 分钟：秒级，例如 `20s前`；
  - 大于等于 10 分钟且小于 1 小时：分钟级，例如 `12分钟前`；
  - 大于等于 1 小时：小时级。

### 3.7 服务器配置页面

- 页面保留检测服务器与加密数据上传的网络传输功能。
- 当前修改只调整标识展示：显示“上传标识 (HMAC)”，不再显示用户 ID。
- 测试连接和开始/停止加密上传仍复用原有 ViewModel / UploadManager 逻辑。

## 4. 数据契约

### 4.1 `DataPacket`

| 字段 | 说明 |
| --- | --- |
| `packet_id` | UUID。 |
| `device_id_hash` | 稳定上传标识 HMAC。 |
| `base_wall_ms` | 批次创建时的 UTC wall time。 |
| `device_uptime_ns` | 批次创建时的设备 monotonic time。 |
| `ntp_offset_ms` | 可选 NTP 偏移。 |
| `encrypted_sensor_payload` | AES-GCM 密文，格式为 `IV|TAG|ciphertext`。 |
| `metadata` | App 版本、schema、压缩、加密、未压缩大小、处理耗时。 |
| `packet_seq_no` | 全局递增序号。 |
| `sha256` | 密文 SHA-256，用于本地队列校验。 |

### 4.2 `SerializedSensorBatch`

| 字段 | 说明 |
| --- | --- |
| `samples` | 传感器样本列表。 |
| `session_id` | 当前采集/认证会话。 |

### 4.3 `AuthResult`

App 当前使用以下 server 字段：

| 字段 | UI 含义 |
| --- | --- |
| `normalized_score` | 展示分数。 |
| `threshold` | 服务端阈值。 |
| `accept` | 认证通过/不通过。 |
| `interrupt` | 服务端是否要求中断。 |
| `window_id` | 判定窗口编号。 |
| `window_size_sec` | 服务端窗口大小。 |
| `model_version` | 模型名称/版本。 |
| `message` | EMA 或 y-of-x 等服务端判定说明。 |
| `server_timestamp_ms` | 服务端判定时间。 |

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 隐私 | 不上传明文设备 ID 或用户 ID；前台应用包名按当前协议作为 `foreground_app_name` 上下文上传。 |
| 稳定性 | 普通卸载重装后，同一设备的上传标识应保持不变。 |
| 安全 | 数据包内容使用 AES-256-GCM；生产部署应启用 TLS / 证书校验。 |
| 兼容 | App proto 必须与 server `protos/sensor_data.proto` 保持字段号一致。 |
| 可观测 | server 日志应能看到解密、解压、解析、认证结果状态。 |
