# 需求规格说明

## 1. 背景与目标

- 搭建一套持续身份认证采集链路，端到端保障数据安全，从 Android 设备采集→加密→上传→Server 解密落盘。
- 当前阶段聚焦 **Phase 1 & Phase 2**：传感器链路、端侧加密、网络传输与 Server 入库。
- 本文作为测试阶段的“需求真源”，覆盖被测范围、必备字段、连接方式与 UI 逻辑期望。

## 2. 范围

| 范围 | 说明 |
| --- | --- |
| Android App | `android/ContinuousAuthentication` 整体，包含 `SensorCollectorImpl`、`SmartTransmissionManager`、`UploaderImpl`、UI（`MainActivity`+Fragments）等 |
| Server | `server/src` FastAPI 服务，`/api/v1/sensor-data` 接口、解密/解压/校验/持久化链路 |
| 加密/协议 | `EnvelopeCryptoBox` + Protobuf `sensor_data.proto` + HTTP Header 约定 |

## 3. 用户与前提条件

1. **用户角色**
   - 终端测试用户：安装 App，授予传感器、前台应用、忽略电池优化等权限，启动采集。
   - Server 运维：部署 FastAPI 服务，准备共享密钥（当前为固定 `Continuous_Authentication`）、开放 `8000` 端口或容器环境。
   - 测试 / QA：并行验证端侧 UI、链路正确性与 Server 数据落盘。
2. **设备前提**
   - Android 10+（API 29）且拥有加速度计、陀螺仪、磁力计。
   - 允许 `USAGE_STATS`、`FOREGROUND_SERVICE`、`WAKE_LOCK`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`、`INTERNET` 权限。
3. **网络前提**
   - 首选 HTTPS/gRPC (TLS1.3)，Wi-Fi 或 4G/5G。
   - Server 端默认监听 `0.0.0.0:8000`，反向代理需透传自定义 Header。

## 4. 功能性需求

### 4.1 传感器采集

| 项目 | 需求 |
| --- | --- |
| 采集组件 | `SensorCollectorImpl`（`SensorManager` + 单线程 Dispatcher） |
| 传感器 | `TYPE_ACCELEROMETER`(200Hz)、`TYPE_GYROSCOPE`(200Hz)、`TYPE_MAGNETIC_FIELD`(100Hz) |
| 窗口策略 | 固定 1s 无重叠窗口，窗口结果写入 `currentWindowSamples` |
| 时间基准 | `event.timestamp (elapsedRealtimeNanos)` + `EnhancedTimeSync` 的 `base_wall_ms` 与 `ntp_offset_ms` |
| 前台信息 | `ForegroundAppDetector` 记录 `foregroundAppHash`，用于上下文行为分析 |

### 4.2 数据打包与加密

1. `SensorDataProcessor`/`DataPacketBuilder` 负责：
   - 将窗口样本转为 `SerializedSensorBatch`（包含 `user_id_hash`、`session_id`）。
   - 默认压缩：`CompressionManager` -> `GZIP`，小于 256B 跳过压缩。
   - 构建 `DataPacket`（字段见 §6）。
2. 加密：
   - `EnvelopeCryptoBox` 使用 Google Tink，生成会话级 DEK（AES-256-GCM），并使用服务器公钥 HybridEncrypt 包装。
   - 所有 ID（device/user/app）通过 HMAC 派生为 Hash，原始值不出端侧。

### 4.3 网络与缓存

| 功能 | Android 侧需求 |
| --- | --- |
| 连接方式 | **优先 gRPC 双向流**（`UploaderImpl` -> `SensorDataService.StreamSensorData`），TLS1.3 + SPKI Pinning。<br/>Server Rest API `/api/v1/sensor-data` 作为 Lite 版对接（通过 HTTP POST，Header `X-Device-ID-Hash/X-Session-ID/X-Packet-Sequence`，Body 为 AES-GCM 密文 + 可选压缩）。 |
| 保活/重连 | `UploaderImpl` -> OkHttp gRPC Channel keepAlive(30s)，ACK 超时 10s 触发重试，指数退避 1s-30s。 |
| 离线缓存 | `InMemoryBuffer`（Channel 队列，默认 10k 包）+ `FileQueueManager`（Room+文件队列，200MB 上限），`UploadManager` 负责调度、Retry、ACK 删除。 |
| 策略下发 | 服务器通过 `ServerDirective.PolicyUpdate`（proto）更新批次间隔、压缩算法、启用传感器列表；客户端 `PolicyManager` 落地 DataStore。 |
| 隐私暂停 | `PrivacyManager` 未授权时禁止 `startCollection()`；撤回同意触发 `withdrawConsentAndDeleteData()` 清空本地。 |

### 4.4 UI & 交互

| 页面 | 逻辑 / 显示要求 |
| --- | --- |
| `MainActivity` Dashboard | 展示采集状态（RUNNING/PAUSED/STOPPED/ERROR）、各传感器状态、网络质量（`NetworkState` 枚举）、连接状态、上传统计。`btnToggleCollection` 切换服务，`btnToggleChart` 控制实时波形。 |
| `SensorDataFragment` | Canvas 波形实时渲染，支持缩放/多传感器叠加，帧率≤30fps。 |
| `ServerConfigFragment` | 配置 server endpoint、TLS pin，显示当前策略、证书状态，允许触发连通性探测。 |
| 对话框 | 首次进入显示 `PrivacyAgreementDialog`、`UsageStatsPermissionDialog`、`BatteryOptimizationDialog`，必须在通过前禁止启动采集。 |

### 4.5 Server 功能

| 模块 | 需求 |
| --- | --- |
| API | `POST /api/v1/sensor-data`（body: `application/octet-stream`），`GET /health` 返回 `storage_stats`、`version`。 |
| 解密 | `AESDecryptor` (AES-256-GCM)，IV(12B)+TAG(16B)+CIPHERTEXT，密钥由 `.env` `ENCRYPTION_KEY` (默认 `Continuous_Authentication`) 派生。 |
| 解压 | `DataDecompressor` 支持 LZ4/GZIP 自动检测。 |
| 校验 | `PacketValidator` (Pydantic) 约束 `timestamp` 范围、`packet_seq_no` 与 Header 一致、窗口合法。 |
| 存储 | `FileStorage` 将 JSON 包写入 `data_storage/{device_hash}/session_{session}.jsonl`，附加 `server_received_timestamp`。 |
| 日志 | 结构化 JSON 日志（`python-json-logger`），记录请求大小、错误原因。 |

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 安全 | 端侧：Envelope AES-256-GCM + HybridEncrypt + HMAC Hash + TLS1.3/Pinning；服务端：仅接受 HTTPS/TLS 反向代理、固定密钥部署。 |
| 性能 | Android 采集 200Hz*2 + 100Hz；窗口压缩+加密耗时 < 50ms；内存使用 < 5MB；Server 单请求 ≤10MB。 |
| 可靠性 | 网络断开 30s 内自动重连；离线缓存不丢包；ACK 才删除本地文件。 |
| 观测性 | Android `MetricsUploader` 周期性上报（待后端实现）；Server `/health` + JSON 日志。 |
| 合规 | 用户可随时撤回同意并清空数据；所有本地缓存遵守保留期配置。 |

## 6. 数据契约（关键字段）

### 6.1 `DataPacket`（Proto）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `packet_id` | string | UUID |
| `device_id_hash` | string | HMAC(device_instance_id) |
| `base_wall_ms` | int64 | NTP 校正后的 UTC |
| `device_uptime_ns` | int64 | elapsedRealtime 基准 |
| `ntp_offset_ms` | int64 optional | 上次同步偏移 |
| `encrypted_sensor_payload` | bytes | GZIP 压缩后经 AES-256-GCM 加密的 `SerializedSensorBatch` |
| `encrypted_dek`/`dek_key_id` | bytes/string | Envelope 信息 |
| `metadata` | `Metadata` | app 版本、传输策略、压缩算法等 |
| `packet_seq_no` | int64 | 由 `EnvelopeCryptoBox` 递增 |
| `sha256` | bytes | Payload 校验 |

### 6.2 HTTP 上传契约

```
POST /api/v1/sensor-data
Headers:
  Content-Type: application/octet-stream
  X-Device-ID-Hash: <string>
  X-Session-ID: <string>
  X-Packet-Sequence: <int>
Body:
  IV(12B) + TAG(16B) + CIPHERTEXT  (ciphertext 可再封装 gzip/lz4)
Response: 200 {"status":"ok"} 或 4xx/5xx {"status":"error","reason":...}
```

### 6.3 Server Directive（gRPC）

- `Ack`: `packet_id`、`creation_server_ts`、`success`、`error_code`、`retry_after_ms`。
- `PolicyUpdate`: `batch_interval_ms`、`max_payload_size_bytes`、`transmission_profile`、`compression_algorithm`、`enabled_sensors`、`sensor_sampling_rates`、`anomaly_config`。
- `KeyRotationNotice` / `EmergencyStop` 预留。

## 7. 配置与依赖

| 系统 | 配置 |
| --- | --- |
| Android | `gradle.properties` 指定 Kotlin/JVM 版本；Hilt 注入；`local.properties` 配置 SDK；`.proto` 编译生成 gRPC stub。 |
| Server | `.env`（可由 `.env.example` 复制）：`PORT`, `DATA_STORAGE_PATH`, `ENCRYPTION_KEY`, `LOG_LEVEL` 等。Docker Compose 默认挂载 `data_storage/`、`logs/`。 |
| 密钥分发 | 当前 Lite 阶段使用固定对称密钥；`EnvelopeCryptoBox` 仍生成 DEK/HMAC，便于后续与 Server KMS 集成。 |
