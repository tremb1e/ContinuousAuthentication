# 偷用防护界面简化与 Android 16 验证

## 改动范围

版本为 `1.1.2` / `versionCode 6`，`compileSdk` 和 `targetSdk` 均为 36。主代理与三个思考程度为 max 的子代理分别通读界面、设置/存储以及采集/上传等核心代码；交叉复核导航和停止流程。

- 首页改为“偷用防护”，副标题按需求替换。提供独立的“启用认证”和“关闭认证”；关闭同时停止认证、三种传感器采集和上传。
- 防护方式跳转设置并展开、定位防护设置；修正导航恢复旧返回栈导致无法回到首页的问题。
- 认证结果分析默认折叠，展开后显示；收起再展开保留筛选和选中时段。删除指定说明和重复启动按钮。
- 小时/天柱状图按屏幕宽度均分，24 小时或 7 天全部显示，不再横向滚动。窄屏使用稀疏坐标，点击柱条可查看具体时段；无障碍标签保留每柱次数。夏令时日期按实际 23/25 小时显示。
- 修复自选日期弹窗在短横屏和 2 倍字号下日历被标题挤出屏幕的问题，保留固定取消/完成操作和可滚动日历。
- 数据采集与知情同意合并，单一开关统一控制三种传感器，操作在说明上方。旧版只关闭部分传感器的配置迁移为全部关闭，避免升级擅自打开已禁用的传感器。
- 防护设置只提供仅监测和即时警示；旧 `OFF` 值归一化为仅监测，迁移不会自动启动认证。
- 删除独立采集上传入口、维护工具及其导出/调试/轮换功能、详情诊断栏。移除未注册的旧 Activity、对应布局/菜单和无调用的旧服务器 ViewModel，保留传感器页的曲线功能。
- 认证记录固定保留 30 天，传感器缓存固定保留 7 天；界面不能修改。启动、运行期间和上传路径统一执行过期清理与过滤；删除失败的过期包也不能再次上传。首页仍默认提供近 7 天的分析。

## 停止与并发修复

关闭操作先关闭上传闸门，再让已接收样本完成本地加密落盘并停止服务，避免慢磁盘排空期间继续发送队列。认证启动和结果提交检查用户是否仍请求运行，防止停止后迟到响应重新激活认证。

上传连接重试统一由 UploadManager 管理，移除 UploaderImpl 独立的重试循环，避免服务停止后被遗留任务重新连接。停止完成的确认还覆盖启动命令排队、通知栏关闭、用户撤回同意等场景。

## 验证边界

本地设备为专用 ARM64 redroid / Android 16 API 36，软件渲染，实际内存页为 4 KB。该环境可验证页面、生命周期和平台 API，不能替代实体手机传感器精度、厂商后台限制、长期功耗或生产身份模型误报/漏报评估。未宣称有限测试能证明所有场景绝无缺陷。

保持现有服务端兼容加密协议；静态共享密钥、AAD/密钥轮换的协议升级仍需服务端配合。服务端自动删除接口仍未实现，界面明确区分本地删除完成与远程删除待处理。没有使用当前错误的服务器地址宣称真实认证服务已通过。
