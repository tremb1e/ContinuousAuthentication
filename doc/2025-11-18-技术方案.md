# 技术方案说明

## 1. 总体架构

```
┌──────────────────────────┐
│        Android App       │
│  (MVVM + Repository)     │
│                          │
│ SensorCollector  ─┐      │
│  └→ SensorDataProcessor  │
│      └→ CompressionMgr   │
│      └→ EnvelopeCrypto   │
│      └→ DataPacketBuilder│
│      └→ Buffer/FileQueue │
│      └→ UploadManager    │
│             └→ Uploader(gRPC/TLS) ────────────────┐
└──────────────────────────┘                        │
                                                   ▼
                                          ┌────────────────┐
                                          │  FastAPI Server│
                                          │  /api/v1/sensor│
                                          │  AES→Decompress│
                                          │  →Validate→JSONL│
                                          └────────────────┘
```

- **通信协议**：端侧默认 gRPC 双向流 (`SensorDataService`)，Lite Server 提供 HTTP POST 以验证加密/压缩兼容性。
- **数据格式**：Protobuf `DataPacket` + Envelope AES-GCM，压缩优先 GZIP，可回落 LZ4。
- **安全**：端到端 AES-256-GCM、服务器固定密钥（待接入 KMS）、TLS1.3 + 证书 Pinning、隐私管理。

## 2. Android 技术细节

### 2.1 关键组件映射

| 模块 | 文件 | 关键职责 |
| --- | --- | --- |
| 应用壳 | `ContinuousAuthApplication.kt` | 初始化 Hilt & NTP 同步 |
| 时间同步 | `time/EnhancedTimeSync.kt` | NTP（pool.ntp.org），定时同步，提供 `convertToAbsoluteTime()` |
| 传感器采集 | `sensor/SensorCollectorImpl.kt` | 注册传感器，单线程 Dispatcher，1s 窗口批处理 |
| 数据处理 | `processing/SensorDataProcessor.kt` | Flow chunk、序列化、压缩、加密、分片（目前禁止分片） |
| 压缩 | `compression/CompressionManager.kt` | GZIP/LZ4，阈值 256B |
| 加密 | `crypto/EnvelopeCryptoBox.kt` | Google Tink，Envelope AES-256-GCM，HMAC Hash，DEK 轮换 |
| 数据包构建 | `data/DataPacketBuilder.kt` | 生成 `DataPacket`、`Metadata`，写入 hashed ID/Session |
| 缓存 | `buffer/InMemoryBufferImpl.kt` + `storage/FileQueueManager.kt` | Channel 队列 + Room/磁盘 JSONL，支持 200MB 容量控制 |
| 上传调度 | `network/UploadManager.kt` | 连接服务器、批量出队、处理 ACK/Policy |
| gRPC 上传器 | `network/UploaderImpl.kt` | TLS1.3 OkHttp channel、双向流、ACK 跟踪、重连、策略更新 |
| 网络探测 | `network/NetworkEnvironmentDetector.kt` | 监控 Wi-Fi/蜂窝质量，提供 `TransmissionConfig` |
| 服务层 | `service/DataCollectionService.kt` | 前台服务 + 通知 + 广播响应 |
| UI 层 | `ui/MainActivity.kt`、`ui/viewmodels/MainViewModel.kt` 等 | 展示状态、控制采集、图表渲染、服务器配置 |
| 隐私 | `privacy/PrivacyManager.kt` | EncryptedSharedPreferences，撤回同意、删除数据 |

### 2.2 数据打包与加密流程

1. `SensorCollectorImpl` -> `SensorSample`（含 `SensorType`、`eventTimestampNs`、`seqNo`、`foregroundApp`）。
2. `SensorDataProcessor.chunked()` 每 1 秒输出 `List<SensorSample>`。
3. `SerializedSensorBatch`：  
   - `samples`: proto 列表  
   - `user_id_hash`: `EnvelopeCryptoBox.getUserIdHash(userId)`  
   - `session_id`: 来自 `UserIdManager`
4. `CompressionManager.compress()` -> 默认 GZIP，保留 `compressionType` 给 Metadata。
5. `EnvelopeCryptoBox.encrypt()`：  
   - 维护 `sessionDEK`（1 小时轮换）+ `dek_key_id`（存 EncryptedSharedPreferences）。  
   - `encrypted_sensor_payload` = AES-256-GCM(plaintext, aad=`packetId+metadata`)。  
   - `encrypted_dek` = HybridEncrypt(server_public_key, sessionDEK)（目前 server-lite 未解封 enveloped DEK，仍保留字段）。
6. `DataPacketBuilder` 写入 `base_wall_ms`、`device_uptime_ns`、`metadata` (app version、schema、transmission profile、compression、encryption scheme)。  
7. 生成 `packet_seq_no`（`EnvelopeCryptoBox` 内 AtomicLong）。

### 2.3 网络与连接策略

- **gRPC** (`network/UploaderImpl.kt`)
  - Channel：`OkHttpChannelBuilder` + `TlsSecurityManager.configureTlsForChannelBuilder()` 强制 TLS1.3。
  - KeepAlive：30s ping，超时 5s。
  - ACK：ServerDirective.ack -> latency 统计、`pendingAcks` Map。
  - 重连：`startReconnect()` 指数退避 1s→2s→4s（上限 30s），最多 3 次。
  - Policy：`PolicyUpdate` 下发 -> `PolicyManager.updatePolicy()` -> 回调 `SmartTransmissionManager.updatePolicy()`。
  - KeyRotation / Emergency：占位 TODO。
- **HTTP（Lite Server 对接）**
  - 待实现的 `Uploader` adapter 可将 `DataPacket` 转换为 server-lite JSON（`PacketValidator` schema）并走 `/api/v1/sensor-data`，当前测试阶段使用工具脚本或 server mock。
- **网络判断**
  - `NetworkEnvironmentDetector` 读取 Wi-Fi RSSI/LinkSpeed & Telephony networkType/signal，发布 `NetworkState`。
  - `UploadManager` 可切换 WiFi-only 模式，`TransmissionConfig` 控制并发/超时/重试。

### 2.4 缓存与可靠性

- `InMemoryBuffer`：`Channel<DataPacket>`，默认容量 10k，统计 `totalEnqueued/Dequeued`。
- `FileQueueManager`：Room 表 `BatchMetadata`（packetId，filePath，status，ntpOffset，sha256 ...）。  
  - 写文件采用 tmp→fsync→rename，计算 SHA256。  
  - 磁盘检测：总大小>200MB 或 可用空间<50MB 时触发 `performCleanup()`（删除最旧/ACK 包）。  
  - 支持 `updateAckStatus`/`updateFailedStatus`/`updateRetryInfo`。
- `ResumableUploader`：监听网络状态，30s 扫描失败包并调用 `uploader.sendDataPacket()` 重传。

### 2.5 安全与隐私

- `EnvelopeCryptoBox` 内部：
  - 使用 AndroidKeysetManager / EncryptedSharedPreferences 保存 Master Key、HMAC Key、deviceInstanceId。
  - 维护 `packetSeqNo`、DEK 生命周期（1h），失败计数超过 5 触发安全开关（TODO）。
  - 对外暴露 `getDeviceIdHash()`、`getAppPackageHash()`、`getUserIdHash()`。
- TLS：
  - `TlsSecurityManager` 配置 TLS1.3 cipher suites、证书 Pinning（SPKI sha256/），可 `extractSpkiPin()`。
  - 当前 gRPC 通道 `hostnameVerifier` 临时允许所有主机名（测试阶段），生产需开启 pin 校验。
- 隐私：
  - `PrivacyManager` 记录 consent timestamp、retention days，支持撤回后删除 Room 文件、缓存、SharedPreferences、UserId。
  - `DataDeletionService` gRPC 端点待实现；目前 `sendServerDeletionRequest()` Stub 返回成功。

## 3. 数据与协议

### 3.1 Protobuf 架构

- `sensor_data.proto` 定义 `DataPacket`、`SerializedSensorBatch`、`SensorSample`、`ServerDirective`、`PolicyUpdate`、`Heartbeat` 等。
- gRPC Service：  
  - `rpc StreamSensorData(stream DataPacket) returns (stream ServerDirective)`  
  - 另外 `GetInitialPolicy`、`SendHeartbeat`、`ReportMetrics` 预留。

### 3.2 Server JSON Schema（Lite）

`PacketValidator` 结构：

```json
{
  "device_id_hash": "string/int",
  "session_id": "string/int",
  "packet_seq_no": 1,
  "timestamp_ms": 1643723400000,
  "window_start_ms": "...",
  "window_end_ms": "...",
  "type": "sensor|event|mixed",
  "foreground_package_name": "pkg",
  "sensor_data": [
     {
       "sensor_name": "accelerometer",
       "sensor_type": 1,
       "timestamp_ns": 123,
       "values": {"x":0.1,"y":0.2,"z":9.8},
       "accuracy": 3
     }
  ]
}
```

Server 端会比较 Header 与 Body 的 device/session/sequence，一致后才写入。

## 4. Server 技术细节

| 组件 | 代码 | 说明 |
| --- | --- | --- |
| 入口 | `src/main.py` | FastAPI + Hypercorn (HTTP/2 h2c)，注册 `/health`、`/api/v1/sensor-data` |
| 配置 | `src/config.py` | `BaseSettings`，支持 `.env`，含 `data_storage_path`、`encryption_key`、`max_request_size` 等 |
| API | `src/api/sensor_data.py` | 接收请求、调用解密/解压/校验/存储，写 structured log |
| 解密 | `src/crypto/decryption.py` | `hashlib.sha256(key)` 派生 AES key，GCM 模式 |
| 解压 | `src/crypto/decompression.py` | 魔数识别 LZ4/GZIP，fallback GZIP |
| 校验 | `src/validators/packet_validator.py` | Pydantic 模型+自定义 validator |
| 存储 | `src/storage/file_storage.py` | `aiofiles` 异步写 JSONL，记录 `server_received_timestamp` |
| 状态 | `src/api/health.py` | `FileStorage.get_storage_stats()` 统计设备/Session/大小 |
| Logging | `src/utils/logging_config.py` | 控制台+文件双写，JSON 格式（`pythonjsonlogger`） |

### 4.1 部署/运行

- 依赖：Python 3.11+，`cryptography`、`lz4`、`fastapi`、`python-json-logger` 等。
- 启动：`pip install -r requirements.txt && python -m src.main` 或 `docker-compose up --build`。
- 数据路径：默认 `./data_storage`，需持久化；日志 `./logs/server_YYYYMMDD.log`。
- 最大请求：`max_request_size = 10MB`，超出返回 413。

## 6. 配置/变更指引

- **Android endpoint**：默认占位 `"your-server-endpoint"`，可在 `ServerConfigFragment` 或 Hilt 注入中覆盖，联测时需统一 gRPC/HTTP 方案。
- **密钥**：Server `.env` `ENCRYPTION_KEY` 必须与 Android `EnvelopeCryptoBox` 派生保持一致（当前为了便捷，端侧 AES 层仍使用固定字符串 `Continuous_Authentication`，Envelope 字段暂未由 server 解析）。
- **证书 Pin**：`PolicyManager` 的 `SecurityConfiguration.pinnedCertificates` 控制 `TlsSecurityManager` 行为，格式 `sha256/xxxx`。
- **NTP**：`EnhancedTimeSync.startPeriodicSync()` 默认 1h，可通过策略调整（TODO）。
